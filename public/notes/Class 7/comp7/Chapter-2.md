• **Chapter Overview**: Welcome to the DAV Dictionary Academic Notes for Class 7 Hands-On in Computer / ICT, Chapter 2, titled "Scratch-I", designed to introduce students to visual programming.
• **Introduction to Programming**: Programming is defined as the process of giving step-by-step instructions to a computer to perform specific tasks or solve particular problems.
• **Traditional vs. Visual Programming**: While traditional programming languages require memorizing complex syntax, spelling, and grammar rules, visual programming languages simplify this process.
• **Introduction to Scratch**: Scratch is a popular, free, graphical programming language developed by the Lifelong Kindergarten Group at the MIT Media Lab.
• **Target Audience of Scratch**: Scratch is primarily designed for children and beginners to learn coding concepts without the frustration of syntax errors.
• **Core Philosophy**: The core philosophy of Scratch is "Imagine, Program, Share," encouraging creativity, logical reasoning, and collaboration among students.
• **Media Creation in Scratch**: Using Scratch, students can easily create their own interactive stories, video games, animations, and mathematical simulations.
• **Object-Oriented Concept**: Scratch projects are built using objects called **Sprites** and a background known as a **Stage**, mimicking a theatrical play.
• **Visual Nature of Blocks**: Instead of typing lines of text code, users in Scratch snap together color-coded visual blocks like puzzle pieces to build scripts.
• **Accessibility**: Scratch is available as both an online editor (accessible via web browsers) and an offline editor (downloadable for desktop use).
• **User-Friendly Interface**: The Scratch interface is designed to be intuitive, vibrant, and user-friendly, catering specifically to middle school learners.
• **Multilingual Support**: Scratch supports multiple languages worldwide, making programming accessible to students from diverse linguistic backgrounds.
• **Global Online Community**: The Scratch website hosts a vast online community where users can share their creations, remix projects, and learn from others.
• **Computational Thinking**: Working with Scratch helps students develop essential 21st-century skills such as computational thinking, problem-solving, and algorithmic design.
• **Role in DAV Curriculum**: This chapter lays the foundational groundwork for understanding algorithmic logic before progressing to advanced coding paradigms in higher classes.

• **Starting Scratch (Desktop Version)**: To open the offline version of Scratch on a school computer running Windows, navigate through the Start menu or double-click the desktop shortcut.
• **Starting Scratch (Web Version)**: To use the online version, open any web browser, navigate to the official Scratch website (scratch.mit.edu), and click on the "Create" button.
• **Scratch Window Layout**: The Scratch main window (or interface) is divided into several distinct panes and panels, each serving a unique function in project development.
• **The Stage**: The Stage is the main working area located at the top-right of the Scratch interface where the final output, animations, and games execute.
• **Stage Dimensions**: The standard Scratch Stage has a fixed dimension of 480 units wide (X-axis) and 360 units high (Y-axis).
• **Cartesian Coordinate System**: The center of the Stage represents the origin point where the X-coordinate is 0 and the Y-coordinate is 0 ($X:0, Y:0$).
• **X-Axis Range**: On the Scratch Stage, the X-axis ranges horizontally from -240 (extreme left) to +240 (extreme right).
• **Y-Axis Range**: On the Scratch Stage, the Y-axis ranges vertically from -180 (extreme bottom) to +180 (extreme top).
• **Green Flag**: The **Green Flag** is a universal control button shaped like a green flag located above the Stage used to run or execute scripts.
• **Stop Sign**: The **Stop Sign** is a red octagonal button located beside the Green Flag used to halt all active scripts and stop project execution immediately.
• **Presentation Mode**: The Presentation Mode button allows users to expand the Stage to full-screen view for testing and showcasing completed projects.
• **Grid/Backdrop Option**: Users can toggle grid lines on the Stage to precisely measure and position sprites using their coordinate values.
• **Sprite Info Pane**: Located beneath the Stage, the Sprite Info pane displays key details about the currently active sprite, including its name, X/Y position, direction, and visibility status.
• **Sprite Name Field**: The Sprite Name field allows users to assign meaningful, descriptive names to sprites rather than keeping default names like "Sprite1".
• **Size and Direction Controls**: In the Sprite Info pane, numeric boxes allow users to scale the sprite size by percentage and adjust its rotational direction smoothly.

• **Understanding Sprites**: A **Sprite** is defined as a graphic object, character, or image that performs actions on the Scratch Stage according to assigned instructions.
• **Default Sprite**: When a new Scratch project is initialized, the default sprite loaded automatically is the **Scratch Cat**, an orange feline mascot.
• **Sprite List Panel**: The **Sprite List Panel** is located below the Stage, displaying thumbnail icons of all sprites currently added to the project.
• **Adding New Sprites**: Users can add new sprites to their project by clicking the **"Choose a Sprite"** button located at the bottom-right corner of the interface.
• **Sprite Library Categories**: The Sprite Library categorizes characters into logical groups such as Animals, People, Fantasy, Dances, Music, Sports, Food, Fashion, and Letters.
• **Painting a Sprite**: The **"Paint"** option opens the built-in vector/bitmap drawing editor, allowing users to draw and design custom sprites from scratch.
• **Surprise Sprite**: The **"Surprise"** option automatically selects and inserts a random sprite from the official Scratch library into the project workspace.
• **Uploading a Sprite**: The **"Upload Sprite"** option permits users to import custom image files (PNG, JPG, SVG) stored locally on the computer to use as sprites.
• **Deleting a Sprite**: Sprites can be permanently deleted from a project by clicking the small "X" or trash can icon on the sprite thumbnail in the Sprite List.
• **Duplicating Sprites**: Right-clicking a sprite thumbnail and selecting "duplicate" creates an exact copy of the sprite along with all its attached scripts and costumes.
• **Exporting Sprites**: Sprites can be saved locally as individual `.sprite3` files to be imported and reused in future programming projects.
• **Sprite Costumes**: Every sprite can possess multiple **Costumes**, which are different graphical appearances or poses for that single character.
• **Costume Tab**: Clicking the **Costumes Tab** opens the integrated graphics editor where users can modify, flip, rotate, or redraw sprite appearances.
• **Animation via Costumes**: Rapidly switching between different costumes sequentially creates the visual illusion of motion, such as walking, running, or talking.
• **Multiple Sprites Interaction**: Scratch projects often feature multiple sprites interacting, conversing, or playing games with one another simultaneously.

• **Understanding Backdrops**: A **Backdrop** refers to the background image or visual setting displayed behind the sprites on the Scratch Stage.
• **Default Backdrop**: By default, a new Scratch project opens with a plain, blank white backdrop filling the entire Stage area.
• **Stage Pane Selection**: To modify the background, users must first click on the Stage thumbnail located to the left of the Sprite List panel.
• **Backdrop Library**: Clicking the **"Choose a Backdrop"** button opens a categorized library containing indoor, outdoor, space, underwater, and patterned background images.
• **Backdrop Categories**: The Backdrop Library is systematically sorted into categories such as Fantasy, Music, Sports, Outdoors, Indoors, Space, and Patterns.
• **Painting a Backdrop**: The **"Paint"** option in the backdrop menu opens the drawing tools, enabling users to create custom background scenes manually.
• **Surprise Backdrop**: Selecting the **"Surprise"** backdrop option randomly assigns an appealing background image from the system repository.
• **Uploading a Backdrop**: Users can upload external digital photographs or downloaded scenic images from their computer disk to serve as project backdrops.
• **Backdrops Tab**: Selecting the **Backdrops Tab** reveals the graphical editor used to edit, paint, or add text elements to existing background scenes.
• **Multiple Backdrops**: A single project can store multiple backdrops, allowing programmers to change scenes dynamically as a story or game progresses.
• **Backdrop Switching Logic**: Programming blocks found in the "Looks" category enable developers to switch from one backdrop to another based on specific events.
• **Enhancing Visual Appeal**: Appropriate backdrops establish the theme, mood, and context of the game, story, or animation being built in Scratch.
• **Backdrop Deletion**: Unwanted backdrops can be easily deleted by hovering over the backdrop thumbnail in the Stage backdrop list and clicking the delete icon.
• **Renaming Backdrops**: Each backdrop can be given a specific name to make script referencing easier when programming backdrop-switching conditions.
• **Visual Continuity**: Consistent backdrop management ensures professional aesthetic quality across complex, multi-level Scratch applications.

• **The Block Palette**: The **Block Palette** is the large central-left panel containing all available programming instructions, organized into color-coded functional categories.
• **Coding Categories**: Scratch programming blocks are categorized into distinct groups: Motion, Looks, Sound, Events, Control, Sensing, Operators, Variables, and My Blocks.
• **Motion Category (Dark Blue)**: Motion blocks control sprite movement, coordinate positioning, directional pointing, gliding, and rotation across the Stage.
• **Looks Category (Purple)**: Looks blocks manage sprite visual appearance, costume changes, speech bubbles, graphical effects, size adjustments, and layer ordering.
• **Sound Category (Magenta)**: Sound blocks allow programmers to play audio clips, musical notes, drum beats, change volume, and alter audio pitch effects.
• **Events Category (Yellow)**: Events blocks act as triggers or listeners, waiting for specific actions (like clicking the Green Flag) to start running scripts.
• **Control Category (Orange)**: Control blocks manage program flow using loops (`repeat`, `forever`) and conditional structures (`if-then`).
• **Sensing Category (Light Blue)**: Sensing blocks detect environmental factors, such as sprite touching, mouse clicks, keyboard inputs, and distance measurement.
• **Operators Category (Green)**: Operators blocks perform mathematical calculations (`+`, `-`, `*`, `/`), string manipulations, and logical comparisons (`<`, `>`, `=`).
• **Variables Category (Orange-Red)**: Variables blocks store dynamic data, scores, timers, and user-defined values that can change during project execution.
• **My Blocks Category (Pink/Red)**: My Blocks allows advanced users to create custom, user-defined subroutines and modular functions for clean programming.
• **Coding Area (Script Area)**: The **Coding Area** is the large workspace on the right side of the screen where blocks are dragged, dropped, and snapped together.
• **Scripts**: A **Script** is defined as a sequence of interlocking programming blocks that dictates how a sprite or stage behaves when executed.
• **Color-Coding Logic**: The distinct color coding of block categories ensures quick identification, organized structure, and intuitive navigation for young learners.
• **Tooltips and Help**: Hovering over any block in the palette provides a brief descriptive tooltip explaining its exact functional behavior.

• **Motion Blocks Overview**: Motion blocks dictate spatial positioning, linear travel, rotational angles, and directional heading for any active sprite.
• **Move Steps Block**: The `move (10) steps` block moves the sprite forward in its current direction by the specified number of pixels.
• **Negative Steps**: Entering a negative number in the `move steps` block (e.g., `move (-10) steps`) causes the sprite to move backward.
• **Turn Right Block**: The `turn right (15) degrees` block rotates the sprite clockwise around its center axis by the given angular value.
• **Turn Left Block**: The `turn left (15) degrees` block rotates the sprite counter-clockwise by the specified number of degrees.
• **Go To Block**: The `go to x:( ) y:( )` block instantly teleports the sprite to exact mathematical coordinates on the Stage without showing motion.
• **Glide Block**: The `glide (1) secs to x:( ) y:( )` block moves the sprite smoothly and gradually to specific coordinates over a set duration.
• **Point in Direction Block**: The `point in direction (90)` block sets the exact heading of a sprite: 90 is right, -90 is left, 0 is up, and 180 is down.
• **Point Towards Block**: The `point towards [mouse-pointer v]` block automatically calculates angles to face another sprite or the mouse cursor dynamically.
• **Change X/Y Blocks**: The `change x by (10)` and `change y by (10)` blocks alter specific coordinate values incrementally from the current position.
• **Set X/Y Blocks**: The `set x to (0)` and `set y to (0)` blocks lock a sprite's horizontal or vertical position to a fixed coordinate value.
• **If on Edge, Bounce**: The `if on edge, bounce` block prevents sprites from disappearing off the Stage boundaries by reversing their direction upon contact.
• **Rotation Style Control**: The `set rotation style [left-right v]` block controls whether a sprite flips completely, rotates freely, or stays upright when turning.
• **Reporter Blocks in Motion**: Motion blocks like `x position`, `y position`, and `direction` are round reporter blocks that output real-time coordinate data.
• **Spatial Accuracy**: Utilizing motion blocks correctly is essential for building accurate maze navigation, racing games, and animated cartoons.

• **Looks Blocks Overview**: Looks blocks control the visual presentation, cosmetic state, communication dialogue, and graphical display attributes of sprites.
• **Say Block for Seconds**: The `say [Hello!] for (2) secs` block displays a speech bubble above the sprite containing the specified text for a set time duration.
• **Say Block Permanent**: The `say [Hello!]` block displays a speech bubble indefinitely until another speech block clears or replaces it.
• **Think Block for Seconds**: The `think [Hmm...] for (2) secs` block displays a thought bubble with cloud-like circles indicating internal pondering.
• **Switch Costume Block**: The `switch costume to [costume2 v]` block instantly changes the sprite's current graphical appearance to a named costume.
• **Next Costume Block**: The `next costume` block cycles the sprite sequentially to the next costume in its list, looping back to the first after the last.
• **Switch Backdrop Block**: The `switch backdrop to [backdrop1 v]` block changes the background scene displayed on the Stage.
• **Next Backdrop Block**: The `next backdrop` block advances the Stage background to the subsequent backdrop in the project sequence.
• **Change Size Block**: The `change size by (10)` block increases or decreases the physical size of the sprite relative to its current dimensions.
• **Set Size Block**: The `set size to (100) %` block scales the sprite to an exact percentage of its original, default image size.
• **Graphical Effects**: Scratch supports visual special effects including color, fisheye, whirl, pixelate, mosaic, brightness, and ghost transparency.
• **Change Effect Block**: The `change [color v] effect by (25)` block alters a specific graphical filter parameter incrementally over time.
• **Clear Graphic Effects**: The `clear graphic effects` block instantly resets all visual distortions and filters back to normal appearance.
• **Show and Hide Blocks**: The `show` and `hide` blocks toggle sprite visibility on the Stage, allowing characters to appear and disappear dynamically.
• **Layer Ordering**: The `go to [front v] layer` and `go back (1) layers` blocks manage overlapping sprites, bringing characters to the foreground or background.

• **Sound Blocks Overview**: Sound blocks introduce auditory elements, voiceovers, background music, and sound effects to enrich Scratch projects.
• **Play Sound Until Done**: The `play sound [Meow v] until done` block pauses script execution until the entire selected audio clip finishes playing.
• **Start Sound Block**: The `start sound [Meow v]` block triggers the audio playback while allowing the rest of the script to execute simultaneously.
• **Stop All Sounds**: The `stop all sounds` block immediately silences all audio clips playing across every sprite and backdrop in the project.
• **Change Pitch Effect**: The `change [pitch v] effect by (10)` block modifies the frequency of the sound, making voices sound higher or lower.
• **Set Pitch Effect**: The `set [pitch v] effect to (100)` block locks the audio pitch to a specific parametric sound value.
• **Clear Sound Effects**: The `clear sound effects` block resets all pitch and panning audio filters back to their default baseline settings.
• **Change Volume Block**: The `change volume by (-10)` block decreases or increases the sound output level incrementally.
• **Set Volume Block**: The `set volume to (100) %` block defines the exact audio loudness level on a percentage scale from 0 to 100.
• **Volume Reporter**: The `volume` reporter block outputs the current volume percentage level, useful for conditional sound programming.
• **Sound Tab Integration**: The built-in Sound tab allows users to record microphone audio, trim audio lengths, add fade-ins, or apply robot effects.
• **Audio File Formats**: Scratch supports standard digital audio formats such as WAV and MP3 for custom sound uploads.
• **Multimodal Learning**: Combining visual animation blocks with synchronized sound blocks creates engaging multimedia projects and interactive games.
• **Musical Notes**: Advanced sound extensions allow programming of synthesized musical instruments, tempos, and distinct note frequencies.
• **Auditory Feedback**: Sound blocks provide crucial user feedback during gameplay, such as scoring chimes, jump sounds, or collision alerts.

• **Events Blocks Overview**: Events blocks serve as the vital triggers that initiate script execution based on user input, mouse clicks, or system states.
• **When Green Flag Clicked**: The `when [Green Flag v] clicked` block is the most fundamental event block, starting scripts when the user runs the project.
• **When Key Pressed**: The `when [space v] key pressed` block triggers attached scripts whenever a specific keyboard key is depressed by the user.
• **When Sprite Clicked**: The `when this sprite clicked` block runs code exclusively when the user clicks directly on that specific sprite with the mouse.
• **When Backdrop Switches**: The `when backdrop switches to [backdrop1 v]` block activates scripts automatically whenever the Stage background changes.
• **Loudness Sensing Trigger**: The `when [loudness v] > (10)` block triggers actions when microphone sound input exceeds a specific decibel threshold.
• **Broadcast Blocks**: The `broadcast [message1 v]` block sends a signaling message across the entire project to communicate between different sprites.
• **When I Receive**: The `when I receive [message1 v]` block listens for a specific broadcast signal and executes its attached script upon receipt.
• **Asynchronous Execution**: Events allow multiple scripts to run independently and simultaneously in response to different triggers occurring in the project.
• **Event-Driven Programming**: Scratch relies on an event-driven programming paradigm, meaning code executes only when specific events happen.
• **Avoiding Infinite Triggers**: Careful use of event blocks prevents unintended script overlap and ensures predictable project behavior during testing.
• **Interactive Storytelling**: Event blocks enable users to interactively drive stories by pressing keys to make characters speak or move.
• **Game Controllers**: Combining key press events with motion blocks turns the computer keyboard into a game controller for guiding characters.
• **Message Passing**: Broadcast events facilitate complex coordination, such as signaling game-over screens, changing levels, or initiating enemy attacks.
• **Foundation of Logic**: Mastery of event blocks is essential for transitioning from simple linear animations to complex interactive video games.

• **Saving Projects**: To prevent data loss, projects must be saved regularly by navigating to the File menu and selecting "Save to your computer".
• **Project File Extension**: Saved offline Scratch project files automatically receive the default file extension **`.sb3`**, indicating a Scratch 3.0 file.
• **Loading Existing Projects**: Previously saved projects can be retrieved by selecting "Load from your computer" in the File menu and choosing the `.sb3` file.
• **Project Naming Convention**: Students should always give descriptive, meaningful names to their Scratch project files rather than keeping default project titles.
• **Online Account Sharing**: Users with registered Scratch accounts can share their projects publicly online, enabling global peer review and feedback.
• **Project Remixing**: The Scratch community encourages **remixing**, allowing users to build upon, modify, and improve existing projects shared by other creators.
• **Debugging Basics**: **Debugging** is the systematic process of identifying, analyzing, and removing logical errors or bugs from programming scripts.
• **Testing and Validation**: Regular testing using the Green Flag and Stop Sign ensures that scripts execute logically and produce expected outcomes.
• **Using the Step Feature**: Single-stepping through scripts helps programmers observe block execution order and isolate faulty logic instructions.
• **Community Guidelines**: When sharing projects online, users must adhere to respectful community guidelines, ensuring positive, safe collaboration spaces.
• **Digital Citizenship**: Students learn responsible digital citizenship by respecting intellectual property, giving credit for remixed assets, and avoiding plagiarism.
• **Classroom Assessment**: DAV teachers assess Scratch projects based on creativity, logical script structure, correct use of blocks, and overall functionality.
• **Portfolio Building**: Maintaining a collection of completed Scratch projects serves as a digital portfolio demonstrating computational proficiency.
• **Transition to Scratch-II**: This foundational knowledge of Scratch-I prepares students to explore advanced control loops, conditional statements, and variables in Chapter 3.
