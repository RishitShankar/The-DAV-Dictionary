---

### [BLUE] 🔬 THEORETICAL FOUNDATIONS OF COMPUTATIONAL PROBLEM SOLVING
- 🧠 **Definition of a Problem:** A situation, obstacle, or question that requires a calculated resolution; in computer science, it is defined by a distinct initial state and a target goal state.
- 💻 **The Role of the Computer:** Computers are fundamentally **non-intelligent execution engines**; they possess zero inherent intuition and rely entirely on human-designed problem-solving logic.
- 🔄 **The Computational Pipeline:**
  - 📥 **Input Processing:** Ingestion of raw data and parameters.
  - ⚙️ **Transformation Logic:** Execution of mathematical, logical, and comparative operations.
  - 📤 **Output Generation:** Presentation of finalized results meeting the goal criteria.

---

### [GOLD] 📐 CORE CHARACTERISTICS OF AN EFFECTIVE SOLUTION
- 📌 **Finiteness:** Every algorithm or problem-solving sequence must terminate after a finite, countable number of steps. Infinite loops are fatal flaws.
- 📌 **Definiteness:** Each step must be rigorously defined; instructions must be unambiguous, leaving no room for subjective interpretation by the processor.
- 📌 **Inputs & Outputs:** A valid problem-solving model must accept zero or more well-defined inputs and produce at least one verifiable output.
- 📌 **Effectiveness:** Every instruction must be basic enough to be executed, in principle, by a human or machine using only basic operations.

---

### [RED] ⚡ THE PROBLEM-SOLVING LIFECYCLE
- 🛠️ **Step 1: Understand the Problem** — Dissecting user requirements, identifying knowns and unknowns, and establishing boundary conditions.
- 🛠️ **Step 2: Deconstruct & Modularize** — Breaking down monolithic problems into smaller, manageable sub-problems (*Top-Down Design*).
- 🛠️ **Step 3: Plan the Logic (Algorithm & Flowchart)** — Abstracting the solution away from programming language syntax into pure logic.
- 🛠️ **Step 4: Code & Translate** — Writing syntax-compliant instructions in a high-level language.
- 🛠️ **Step 5: Test & Maintain** — Validating against edge cases and updating over time.

### [BLUE] ⚖️ FUNDAMENTAL LAWS OF LOGICAL CONSTRUCTS
- 📐 **Law of Sequential Execution (Linearity):**
  - $\text{Execution Path} = S_1 \rightarrow S_2 \rightarrow S_3 \rightarrow \dots \rightarrow S_n$
  - *Principle:* Instructions execute strictly in the order they are written, top-to-bottom, unless explicitly diverted by control structures.
- 📐 **Law of Conditional Branching (Selection):**
  - $\text{If } \text{Condition } C \text{ is True } \rightarrow \text{Execute Block } A, \text{ Else } \rightarrow \text{Execute Block } B$
  - *Principle:* Introduces decision-making pathways based on boolean evaluations ($\text{True}/\text{False}$).
- 📐 **Law of Iteration (Repetition/Looping):**
  - $\text{While } \text{Condition } C \text{ is True } \rightarrow \text{Repeat Statement Block } S$
  - *Principle:* Eliminates redundancy by executing blocks of code multiple times until a terminating condition is met.

---

### [GOLD] 🧮 MATHEMATICAL PROBLEM SOLVING EQUATIONS IN COMPUTING
- 📊 **Simple Interest Algorithm Formula:**
  - $\text{SI} = \frac{P \times R \times T}{100}$
  - *Variables:* $P$ (Principal), $R$ (Rate), $T$ (Time).
- 📊 **Area of a Circle Algorithm Formula:**
  - $\text{Area} = \pi \times r^2$
  - *Constant:* $\pi \approx 3.14159$, $r$ = Radius.
- 📊 **Even/Odd Evaluation Logic (Modulo Arithmetic):**
  - $\text{Remainder} = N \pmod 2$
  - If $\text{Remainder} == 0 \rightarrow \text{Even}$, else $\rightarrow \text{Odd}$.

---

### [GREEN] 📌 EFFICIENCY & COMPLEXITY PRINCIPLES
- ⚡ **Space Complexity Principle:** Minimizing the memory footprint by reusing variables and optimizing data types.
- ⚡ **Time Complexity Principle:** Minimizing the total number of operational steps required to reach the output state.

### CHAPTER 6: PROBLEM SOLVING — PAGE 4: EXHAUSTIVE TECHNICAL GLOSSARY & PRECISION DEFINITIONS

---

### [BLUE] 📖 MASTER GLOSSARY OF ICT TERMS
- **Algorithm:** [GOLD] A finite, ordered sequence of unambiguous, step-by-step instructions designed to solve a specific computational problem or perform a task.
- **Flowchart:** [GOLD] A graphical or pictorial representation of an algorithm utilizing standardized geometric symbols connected by directional flowlines.
- **Debugging:** [GOLD] The systematic process of detecting, isolating, locating, and correcting bugs, errors, or anomalies in an algorithm or computer program.
- **Syntax Error:** [GOLD] A compile-time violation of the grammatical and structural rules of a programming language.
- **Logical Error:** [GOLD] A flaw in the algorithm's underlying reasoning that allows the program to run without crashing but produces incorrect, unintended outputs.
- **Terminal:** [GOLD] A flowchart symbol (represented by an oval/capsule) used exclusively to indicate the absolute Start or Stop of a process.
- **Process:** [GOLD] A flowchart symbol (represented by a rectangle) used to denote data manipulation, arithmetic operations, or variable assignment.
- **Decision Box:** [GOLD] A flowchart symbol (represented by a rhombus/diamond) used to pose a question requiring a binary ($\text{True}/\text{False}$) branching outcome.
- **Input/Output (I/O):** [GOLD] A flowchart symbol (represented by a parallelogram) used for data ingestion from input devices or displaying output results.
- **Dry Run:** [GOLD] A manual, mental, or paper-based walkthrough of an algorithm or flowchart step-by-step, tracking variable values to verify logic.
- **Pseudocode:** [GOLD] An informal, high-level description of an algorithm's operational principle that combines natural human language with structural programming conventions.
- **Variable:** [GOLD] A named memory location designated to store mutable data values that can change during program execution.
- **Constant:** [GOLD] A fixed data value that remains invariant and unalterable throughout the entire execution lifetime of the program.
- **Infinite Loop:** [GOLD] A catastrophic execution defect wherein a looping construct lacks a reachable terminal condition, causing endless repetition.
- **Flowline:** [GOLD] Directed arrows connecting flowchart symbols to indicate the precise path and sequence of operational control flow.

### [BLUE] 📖 TEXTBOOK CORE HIGHLIGHTS
- 📌 **Human vs. Machine Logic:** Humans solve problems using intuition, past experience, and abstract reasoning; computers solve identical problems strictly through rigid, deterministic execution of programmed instructions.
- 📌 **Importance of Planning:** Writing code without first formulating an algorithm or flowchart leads to chaotic, unmaintainable software architectures riddled with logical flaws.
- 📌 **The Birth of Flowcharts:** Originating alongside early mechanical and electronic computing, flowcharts became the universal blueprint standard for programmers globally.
- 📌 **Clarity in Algorithms:** An ambiguous instruction like *"Make the number bigger"* is invalid in computer science; it must be precisely stated as *"Set $X = X + 1$"*.

---

### [GOLD] 🌟 KEY DAV TEXTBOOK FACTOIDS
- 💡 **Factoid 1:** Algorithms must always possess an **entry point** and an **exit point**.
- 💡 **Factoid 2:** Flowchart directional arrows must **never cross** if it can be avoided; intersecting flowlines severely degrade readability and indicate poor design.
- 💡 **Factoid 3:** Every decision box in a flowchart must have **at least two outgoing flowlines** (typically labeled True and False, or Yes and No).
- 💡 **Factoid 4:** Variable names in basic algorithms should be descriptive (e.g., using `sum` instead of arbitrary single letters where possible, though single letters like $A, B, C$ are standard for mathematical formulas).
- 💡 **Factoid 5:** The parallelogram symbol is shared for both data reading (Input) and data printing (Output).

### [BLUE] ⚙️ ALGORITHM DESIGN: PRACTICAL WALKTHROUGH
- 📝 **Problem:** Write an algorithm to find the greatest of two numbers entered by a user.
  - **Step 1:** Start.
  - **Step 2:** Read two numbers, $A$ and $B$.
  - **Step 3:** If $A > B$, then display "A is greatest", else display "B is greatest".
  - **Step 4:** Stop.

---

### [GOLD] 🎨 FLOWCHART CONSTRUCTION: PRACTICAL WALKTHROUGH
- 📊 **Mapping the Greatest-Number Problem:**
  - 🟢 **Terminal Symbol (Oval):** `START`
  - 📥 **I/O Symbol (Parallelogram):** `INPUT A, B`
  - 🔶 **Decision Symbol (Rhombus):** `Is A > B?`
    - ➡️ **True Branch:** Points to Parallelogram `PRINT "A is greatest"`
    - ➡️ **False Branch:** Points to Parallelogram `PRINT "B is greatest"`
  - 🔴 **Terminal Symbol (Oval):** Both print paths converge to `STOP`

---

### [GREEN] 🔄 ITERATIVE ALGORITHM EXAMPLE
- 📝 **Problem:** Write an algorithm to print numbers from 1 to 5.
  - **Step 1:** Start.
  - **Step 2:** Initialize $N = 1$.
  - **Step 3:** Print $N$.
  - **Step 4:** Set $N = N + 1$.
  - **Step 5:** If $N \le 5$, go back to Step 3.
  - **Step 6:** Stop.

### [BLUE] 🏆 DAV EXAM GOLDEN HIGHLIGHTS
- 🎯 **Board Expectation 1:** Students must be able to convert a given text-based arithmetic algorithm directly into a standards-compliant flowchart without missing symbols.
- 🎯 **Board Expectation 2:** Precise identification of flowchart shapes is a high-frequency objective question type. Never confuse the Process rectangle with the I/O parallelogram.
- 🎯 **Board Expectation 3:** Always remember to include `START` and `STOP` terminals in every single flowchart; omitting them results in immediate point deductions.

---

### [GOLD] ⚠️ EXAM PITFALLS & WARNINGS
- 🛑 **Trap 1:** Assuming a flowchart can have multiple `START` terminals. A valid program execution thread can originate from only one entry point.
- 🛑 **Trap 2:** Forgetting to update loop control variables (e.g., omitting $N = N + 1$), which inadvertently creates a fatal infinite loop.
- 🛑 **Trap 3:** Using a decision rhombus for simple arithmetic assignment (e.g., writing $X = 5$ inside a diamond instead of a rectangle).

### [BLUE] ⚖️ COMPARATIVE ANALYSIS: ALGORITHM VS. FLOWCHART
- 📝 **Algorithm:**
  - *Nature:* Text-based, written in structured natural language or pseudocode.
  - *Readability:* Requires sequential reading line by line.
  - *Debugging:* Harder to visualize complex branching loops at a glance.
- 🎨 **Flowchart:**
  - *Nature:* Visual, graphical representation using geometric symbols.
  - *Readability:* Immediate visual comprehension of program flow and logic.
  - *Debugging:* Exceptionally easy to trace execution paths and isolate errors.

---

### [GOLD] ⚖️ COMPARATIVE ANALYSIS: SYNTAX ERROR VS. LOGICAL ERROR
- 🛠️ **Syntax Error:**
  - *Cause:* Spelling mistakes, missing semicolons, incorrect keyword usage.
  - *Severity:* Highly visible; compiler flags it immediately.
  - *Fix:* Straightforward typo correction.
- 🛠️ **Logical Error:**
  - *Cause:* Flawed formula, incorrect condition bounds (e.g., using `>` instead of `>=`).
  - *Severity:* Insidious; compiler ignores it, making it extremely difficult to detect.
  - *Fix:* Requires rigorous dry-run desk checking and redesigning the algorithm.
